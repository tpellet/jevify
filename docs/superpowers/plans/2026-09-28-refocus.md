## Goals

Problem:     jevify grew to 13 commands, 42 flags, 443 tests and 10.6k production lines in ten days.
             It has no measured benefit for its primary user (coding agents), no external user, and
             no headline. The owner: "We built too big, too complicated and lost track."
Outcome:     A smaller jevify built around two jobs an agent cannot do cheaply alone:
             `why` (the line that explains a failure) and `fill` / `pick --from` (the exact handle a
             command needs, from a description). Each has an impressive, reproducible use case and
             one measured number. Duplicated code and clutter tests are gone. Real end-to-end
             tests against the live backend prove the pipeline.
Users:       Coding agents (Claude Code, Codex) first; humans at a shell second.
Scope:       Pass 1 declutter (tests, duplicate code). Pass 2 end-to-end tests with real data.
             Pass 3 refocus: drop fluff, fix the decision logic, agent contract, killer features,
             README around one job and one number. Release when a pass leaves `main` shippable.
Non-goals:   Renaming the crate (owner decision). New external services beyond classifier.dev and
             TypeSafe (owner decision). MCP server (later, after the number exists).
Constraints: AGENTS.md rules (one checkout, Agent Mail, no rm/git rm, signed commits, gate before
             commit, gitleaks before push). Owner instruction 2026-09-28 overrides the Testing
             section: prefer end-to-end tests with real data over unit tests.
Success:     Pass 1: tests and test lines cut by at least 40%; every contract in "Keep list" still
             covered; production lines down; gate green. Pass 2: an end-to-end suite runs the real
             binary against the live backend on real repositories and logs, with gold answers.
             Pass 3: the dropped surface is gone; the use cases run as documented; a release ships.
Open:        Crate name (owner). Providers beyond TypeSafe/classifier.dev (owner).

## Keep list: contracts every pass must keep covered by at least one test

1. Exit codes per verb (0, 1, 2, 3, 4, 5, 6, 130 where used). One test per code per verb at most.
2. The `--json` envelope shape and the `error.kind` strings. One schema check per verb.
3. Marker parsing: literal passthrough (`@{u}`, `HEAD@{2}`, `user@host:path`, `@@{`), escapes,
   unknown kind and unterminated marker exit 2.
4. `fill` execution safety: argv[0] literal, no shell, a handle starting with `-` gets `./`,
   dry-run quoting round-trips, nothing runs on abstain or error, the status file.
5. Security: secrets redacted before a request, excerpts withheld for secret files, base URL
   pinned to the backend host, lister environment hardened.
6. Records: byte-exact output, input order, `-0` and `--para` splitting.
7. Backend limits that prevent a rejected request (UTF-16 caps, label counts, keyless batch size).
8. HTTP status mapping (401/403, 402, 413/422, 429, 5xx) and retries; the deadline.
9. The answer cache: a hit, and it stores only redacted input.
10. Security: redirects never receive the key or evidence; the TypeSafe key never goes to
    classifier.dev; user recipes never shadow shipped kinds and never load from the cwd; the
    binary never reads the platform config dir.
11. `add`: stages only the chosen hunks; runs at the repo top level from a subdirectory;
    dry-run, decline, abstain and a `git apply` rejection stage nothing.
12. Agent contracts: stdout carries only handles and records; stdin with two roles is exit 2;
    below threshold, NONE and a tie exit 3; an unsure `@{flag:…}` runs nothing; incomplete
    evidence never gives a whole-input verdict.
13. A lister overflow, failure or deadline is an error, never a partial list.
14. Release script safety (`tests/release.rs`).

The 40% figure is an expectation, not a gate. Each declutter commit maps the contracts its files
covered to the tests that still cover them. Exit codes: at least one test per path.

Delete: tests that pin tuning constants (request counts, window counts, finalists per window),
near-duplicate variants of one behaviour, tests of wording beyond kind, exit and the presence of a
hint, tests of private helpers already covered by a contract test, tests of dead code.

## Pass 2: end-to-end tests (after pass 1 lands)

One suite, `tests/e2e.rs`, runs the release binary against the live backend (TypeSafe key, then
keyless) on real data: a pinned public repository clone, this repository's history, real CI logs
under `evals/why/`, the demo fixtures. Every case has a gold answer and asserts the decision and
the chosen item, never the probability. It absorbs `tests/live.rs` and `tests/transcripts.rs`.
Without a key it prints `SKIPPED` and passes. Built with the `jfp:e2e-pipeline-validator` method.

## Pass 3: refocus (after pass 2 lands; scope finalised from the use-case study)

- Drop: `sort`, `route` (becomes `pick --from tool`), `robot-docs`, `init zsh|bash` and the CNF
  hook, `--format toon|jsonl` and the `toon-format` dependency, `cost_usd` and
  `JEVIFY_PRICE_PER_MTOK`, exit 7. `route` goes only once `pick --from tool` carries what made
  route score 92%: man-page evidence in its evidence round, the tie check, and
  `JEVIFY_INVENTORY_FILE`. `inventory.rs` and `manpage.rs` stay. `jevify init agents` keeps that
  exact spelling. Each drop sweeps its references: cli help, capabilities, SKILL.md,
  ROBOT_MODE.md, PRIVACY.md, README, docs/guide, docs/demo, VISION.md, AGENTS.md, the eval
  scripts, the transcripts table.
- Keyless backend stays on `/v1/classify`: classifier.dev's `/v1/systemone` caps a choice at 26
  options, which would cut keyless reach from 9,801 candidates to about 625.
- Logic: one decision rule (`tournament::decide`) everywhere (stdin `pick`, `why` ambiguity);
  `pick --from` always runs the evidence round for commit, file and dir; the finals text budget
  goes to finalists by rank, not evenly.
- Agent contract: on exit 3, `data.shortlist` holds the top candidates with evidence and score;
  one-line `--json`; compact `capabilities` by default; one-screen `init agents`; `health` reports
  quota and credits; a `quota_exhausted` error kind; HTTP 402 parsed by `error_type`; every
  "20,000 a day" claim replaced by the service's dollar budget.
- `add` without a terminal and without `--yes` is a usage error (exit 2), not a decline.
- Killer features for `why` and `fill` from the use-case study.
- README: one job, one number, one install line (the cargo-dist shell installer).

## Use-case findings (2026-09-28, TypeSafe backend)

- `why`: 11 real failed GitHub Actions runs: root cause at rank 1 in 9, summary line in 1,
  abstain in 1, wrong line in 0; 97-99.8% fewer tokens; 0.7-1.9 s.
- `fill`: `gh pr checkout '@{pr:…}'` found the diff-verified PR among 1,000 in 6.9 s, 424x fewer
  bytes than the listing. The commit kind abstained on 2,287 commits; the `ci-run` recipe times
  out on its 1,000-run listing; one file query picked a wrong file twice (topic association);
  enriched selection echoes up to 4.4 KB on stderr.
